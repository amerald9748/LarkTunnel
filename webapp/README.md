# LarkTunnel · 本地查询台 (webapp)

输入**柜号**或 **ISA** → 实时从飞书多维表格拉取记录 → 表格化展示，可**按视图**筛选。

**只读**。这个应用没有任何写入代码路径 —— 它不会修改生产 Base。

---

## 运行

```bash
python webapp/server.py
```

然后打开 <http://127.0.0.1:8787> 。或直接双击 `webapp/run.bat`（会自动开浏览器）。

换端口：

```bash
LARK_PORT=9000 python webapp/server.py
```

### 依赖

**没有依赖。** 纯 Python 标准库，不需要 `pip install`，也不需要 Node / `lark-cli`。
（本机没装 Node，所以这个工具刻意避开了项目原有的 `lark-cli` 链路。）

---

## 它怎么工作

```
浏览器 ──HTTP──> server.py ──HTTPS──> open.feishu.cn (Bitable OpenAPI)
                     │
                     ├── config/config.js   ← baseToken + 表注册表（单一事实来源）
                     └── config/secrets.txt ← App ID / Secret（仅服务端读取）
```

* `lark_client.py` —— 飞书 API 客户端：鉴权+token 缓存、视图/字段元数据、搜索、值格式化。
* `server.py` —— 极简 HTTP 服务 + JSON API，只监听 `127.0.0.1`。
* `static/` —— 前端（原生 JS，无框架、无外部资源）。

### 安全

* **密钥只在服务端。** App ID/Secret 从 `config/secrets.txt` 读取用于换取
  `tenant_access_token`，**绝不下发到浏览器**，也不写日志。
* **只绑定 127.0.0.1**，不对局域网暴露（因为它能读生产凭据）。
* 全部是读操作，没有 create/update/delete。

## ⚠️ 关于「视图」的重要说明

飞书 API **无法在一个视图内做搜索**：只要你传了自己的 `filter`，它就会
**覆盖掉视图自带的过滤条件**（在本 Base 上对 `/records/search` 和 `/records`
两个接口都实测确认过）。

所以本工具的做法是：

1. 先在**全表**按柜号/ISA 搜索（命中通常只有几十行）；
2. 再把所选**视图自身的过滤条件**在本地逐行判定，筛掉不属于该视图的行；
3. 同时按视图的 `hidden_fields` 隐藏该视图不显示的列。

结果里会显示 `全表 N → 视图内 M（排除 X）`，做到可验证。

**如果某个条件本地无法判定**（未知字段、未支持的操作符），界面会明确提示
`⚠ 无法本地判定的条件：xxx（结果可能偏宽）`，**绝不静默给出错误结果**。

已支持的视图条件操作符：`contains` / `doesNotContain` / `is` / `isNot` /
`isEmpty` / `isNotEmpty`，其中单选/多选/公式选项字段会自动做
option-id → 选项名 映射。

## 📄 上传文件自动识别

把 Excel/CSV 拖进页面上的上传区（或点「选择文件」），自动提取六个字段：

| 字段 | 表头别名（部分） | 识别方式 |
|---|---|---|
| 柜号 / AWB | 柜号、货柜号、**装货明细**、AWB | 表头列 → 行内标注 → 正则（`ABCD1234567`／带后缀 `…B`／`093-9992123`）|
| 客户批次号 | 客户批次号、批次号、批次 | 表头列 → 行内标注（`客户批次号：JF-US26038B`）→ 正则 |
| 仓库供应商 | 仓库供应商、操作仓库、供应商 | 表头列 → 与 3.1 的**实时选项**比对 |
| 目的地路线 | 目的地路线、派送目的地、仓库代码、**仓库** | 表头列 → 与 3.1 的**实时选项**比对，`CA-YVR4`→`YVR4` |
| 预约时间 | 预约时间、预约、时间 | 表头列（含 Excel 序列号换算）→ 日期正则 |
| ISA | ISA、**预约号**、预约编号、预约单号 | 表头列 → `ISA:123456789` / `ISA-000123` / 纯数字列 |

> **`预约号` 就是 ISA**，`预约/时间` 都算预约时间，`仓库`（值形如 YYC4/YEG2）算目的地路线 —— 均按现场口径配置。
> 别名**最长优先**，所以 `仓库供应商` 仍归「仓库供应商」、`仓库代码` 仍归「目的地路线」，不会互相抢。

**支持的日期格式**：`2026-07-24 09:00`、`2026/07/24`、**`07/24/2026 09:00 MDT`**（月在前，
自动保留 MDT/PDT/EST 等时区标记）、Excel 日期序列号。

### 仓库供应商下拉框

上传解析后，`仓库供应商` 卡片是一个下拉框（选项来自 3.1 该字段的**实时选项**，29 个）：

| 解析结果 | 下拉框 | 控制台 |
|---|---|---|
| **Null**（文件里没有） | **可选**，供手动选择 | `console.log("Null")`；选择后再 log 所选值 |
| **有值**（文件里已给出） | 显示该值并**锁定不可选** | — |

逻辑：文件已经给出仓库供应商时无需再选，锁定即可；缺失（Null）时才让人工补选。

### 📦 柜号明细表（每柜对应自己的预约）

除了上面的汇总卡片，还会输出一张**逐柜明细表**，把不同格式的 Excel 统一成一张表：

| 柜号 | 目的地路线 | 预约号/ISA | 预约时间 | 板数 |
|---|---|---|---|---|

- **一柜一约**：每行一个柜号，带自己的预约号与时间。
- **多柜分组**：一个 `装货明细` 单元格里有多个柜号（换行或 `A-10P/B-2P` 形式），
  共用该行的预约号与预约时间，打「分组」标记。
- **板数**（`13P` / `13P-9` / `4箱` / `1箱散货`）原样保留，按柜归属（不串到下一个柜号）。
- 快递/私人地址行（UPS、PUROLATOR、AST…、私人地址码）没有预约的，预约号/时间显示 `Null`。
- 每行右侧「查询」按钮，一键拿该柜号去 3.1 查。
- 每行右侧「**上传**」按钮 + 上方「**预演上传到 5.6（dry-run）**」按钮 →
  写入飞书 **`5.6 预约表`**。见下节。

### ⬆ 上传到 5.6 预约表（含 dry-run + 守卫）

把解析出的每条「柜号→路线→预约号→时间」登记成 5.6 的预约记录。全部写入都有守卫，
逻辑在 `webapp/upload_56.py`：

- **先 dry-run**：点「预演上传到 5.6」→ 出一张清单，每行标注动作：
  `待新建` / `跳过（已存在）` / `拦截`，并给出汇总（新建 X · 跳过 Y · 拦截 Z）。**不写任何东西**。
- **按 ISA 去重**：预约号已存在于 5.6 → 跳过（`console.log("当前派送记录已存在")`）；
  同一批次里同一预约号也只建一次（分组的多柜共用一个预约）。
- **校验目的地**：路线必须是 5.6「目的地」的现有选项；UPS/PUROLATOR/AST/私人地址等 → 拦截，
  **绝不自动新建选项**。
- **预约账号**：取上方所选「仓库供应商」，做映射校验（**VAST→元浩**；`CAL-5505`/`TOR-1140`
  非合法账号 → 拦截）。
- **字段格式**：`ISA` 写为数字；`目的地`/`预约账号` 写为合法单选；`复制时间列` 写为
  文本 `YYYY/MM/DD HH:MM`（对齐 5.6 现存格式）。
- **提交**：dry-run 后若有「待新建」，出现「确认写入 5.6（新建 N 条）」按钮 →
  二次确认 → `batch_create`（带 `client_token` 幂等）。或用每行「上传」按钮逐条写。

API：`POST /api/dryrun_56`（只读预演）、`POST /api/commit_56`（批量写）、
`POST /api/upload`（单条，走同一守卫）。

#### 兼容的两种表格布局（自动识别）

| 布局 | 样子 | 柜号从哪来 |
|---|---|---|
| **A · 出库计划** | 一行一票，`仓库\|预约号\|预约时间\|装货明细`，柜号在 `装货明细` 单元格里（可多柜） | 单元格内正则 |
| **B · 派送计划** | `柜号 CNTR：<柜号>` 标题行 + 其下若干 `派送仓点\|总托数\|预约号\|预约时间` 行；多个柜号纵向堆叠 | 标题行，向下管辖到下一个标题行 |

两种布局都归一成上面同一张明细表。新增识别的表头别名：`派送仓点`（目的地路线）、
`总托数/板数`（板数）、`预约号`（ISA）。`预约号` 列若是文字（如「有了预约时间更新」）
则判为无效 → `Null`。

**识别不到的字段返回 `Null`**（界面上红色 `Null`）。识别到多个值时会显示
「共 N 个不同值」可展开，主值取出现次数最多的那个。每个值都标注了来源
（哪张表的哪一列 / 行内标注 / 正则扫描），便于核对。

识别完可以一键「用柜号查询」或「用 ISA 查询」，直接把值送进上面的查询框。

支持格式：`.xlsx` / `.xlsm` / `.csv` / `.tsv` / `.txt`（`.xls` 请先另存为 `.xlsx`）。

### 识别策略（为什么这样设计）

1. **优先表头**：找到表头行后按列取值。别名匹配**最长优先**，所以 `仓库代码`
   会被识别成「目的地路线」而不是「仓库供应商」。
2. **表头需至少命中 2 个别名**（沿用项目里 `parse-plan.js` 的成熟规则）。
   否则像 `客户批次号：JF-US26038B` 这种标题单元格会被误当成表头，导致整列取错值。
3. **行内标注**：`标签：值` 形式的标题块单独抽取。
4. **正则兜底**：以上都没有时，全表扫描正则 + 实时选项比对。

xlsx 读取优先用 `openpyxl`（能正确处理日期单元格），没装则自动回退到
`zipfile + XML` 的标准库解析器 —— 所以**依然是零硬依赖**。

> **柜号正则的一个坑**：不能用 `\b` 收尾。Python 的 `\w` 把中文算作单词字符，
> `UETU8792061转运` 里 `1` 和 `转` 之间没有词边界，用 `\b` 会**整个匹配不到**。
> 因此用的是 `(?<![A-Z0-9])([A-Z]{4}\d{7}[A-Z]?)(?![A-Z])`，同时让
> `MATU45919300` 仍能取出 `MATU4591930`。
> 另外一个单元格里可能有**多个**柜号，必须 `finditer` 而不是 `search`。

## 使用要点

* **柜号建议用「包含」匹配。** 表里柜号常带后缀（例如 `CAJU5283296` 实际存为
  `CAJU5283296A` / `CAJU5283296B`），精确匹配会查不到。命中后界面会显示
  「匹配值」，把实际柜号列出来。
* 一个柜号通常对应**多行**（按目的地路线拆分）。
* 点击结果表任意一行可展开该记录的**全部非空字段**。
* 时间字段按 `America/Edmonton`（山区时间）渲染，可用环境变量 `LARK_TZ` 改。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 存活检查 |
| GET | `/api/tables` | config.js 里的表注册表 + 可查询字段 + 时区 |
| GET | `/api/views?table=<table_id>` | 该表的全部视图 |
| POST | `/api/query` | `{table, view_id, field_key:"awb"\|"isa", value, mode:"contains"\|"is"}` |
| POST | `/api/parse` | `{filename, content_b64, table?}` → 六字段识别结果（缺失为 `null`）|

`/api/query` 返回：`{ok, count, total_found, view_filter:{excluded,unsupported,...}, matched, rows}`。
